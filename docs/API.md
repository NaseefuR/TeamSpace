# API v1 contract

Base URL: `/api/v1`. Success envelope: `{ "success": true, "data": ..., "meta": ... }`. Errors: `{ "success": false, "error": { "code", "message", "details" } }`. Protected routes use `Authorization: Bearer <access_token>`. OpenAPI is at `/openapi.json`, Swagger UI at `/docs`, and ReDoc at `/redoc`. IDs are UUID strings. Examples abbreviate UUIDs.

Unless stated otherwise, errors are `401` unauthenticated, `403` insufficient role, `404` absent or outside the caller's workspace, `409` uniqueness conflict, and `422` invalid request. Notification emails are enqueued after the in-app notification transaction commits.

The generated Pydantic schemas and operation summaries are in `backend/openapi.json`. Paginated lists use `page` / `page_size` and total count in `meta`. Generic sorting, field selection and idempotency-key behavior are not implemented. Validation currently follows FastAPI's 422 handler; unifying that body with the error envelope is a hardening item. Password reset, email verification, TOTP and session-list endpoints are roadmap items. Messages are retrieved by short polling from the UI; there is no WebSocket/SSE chat stream yet. Notification email delivery uses Brevo via a bounded process-local queue; pending jobs are volatile and are not shared across API replicas.

Task assignment to another workspace member creates an in-app notification in the same database transaction. Notification delivery is currently limited to task assignment; email and other notification triggers remain deferred. Common error examples: `401` `{"success":false,"error":{"code":"UNAUTHORIZED","message":"Invalid or expired access token","details":[]}}`; `403` `{"success":false,"error":{"code":"FORBIDDEN","message":"Insufficient workspace role","details":[]}}`; `404` `{"success":false,"error":{"code":"NOT_FOUND","message":"Project not found","details":[]}}`; `409` `{"success":false,"error":{"code":"CONFLICT","message":"Project key already exists","details":[]}}`; `422` request validation error. Applicable errors for each operation are the common `401/403/404/409/422` set described above; public auth routes return `401` for invalid credentials/tokens and `403` when invite-only registration is closed.

The AI assistant sends the user's question and up to 40 projects plus 60 recent tasks the user may access to the configured OpenAI-compatible chat-completions endpoint. Set `AI_BASE_URL`, `AI_API_KEY`, and `AI_MODEL` in `backend/.env`. The response names records supplied as context; these are not file citations. ZIP ingestion, code search, embeddings, chat persistence, and streaming are not implemented by this endpoint.
